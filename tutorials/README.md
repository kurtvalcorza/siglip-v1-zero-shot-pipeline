## Relation to the SigLIP 2 row

This notebook is the SigLIP 2 row's `E2E` tutorial (`siglip2-vision-language-pipeline`) re-pinned to the 2023 v1 checkpoint: the same six-module package shape, the same corpus, split, baselines, metrics and adaptation recipe, so the two rows can be read side by side. It keeps the three drawn shapes and their inference contract as Section 5 and carries the adaptation contract around it: a real labelled photograph corpus fetched with per-file pins, a classification and retrieval protocol in the carried `metrics.py` (accuracy, macro F1, per-class recall / precision / F1 / AP, text-to-image mAP), two non-neural baselines, a bounded fine-tuning of the vision tower with the model's own sigmoid-scaled logits and SigLIP's pairwise sigmoid loss, a per-species breakdown on two prompt sets, the shapes re-scored after adaptation, and an artifact that reloads. The per-grid `evaluation_report` helper is unchanged; `pipe.evaluate` is the corpus-level stage (`measured` / `measured-small-sample`).

## Conformance notes

- **Standalone carrier (ST1–ST8):** the primary path performs no clone, repository install, or repository import. Section 2 embeds the repository's six modules verbatim in topological dependency order (each tagged `metadata.dimer.embedded_module`; the only rewrites make `DEFAULT_WEIGHTS_DIR` working-directory-relative, replace the `resolve_weights_path` checkout-convenience line and remove internal relative package imports), Section 3 carries the 8-file snapshot manifest inline and asserts it against the module's constants before fetching, and `NOTEBOOK_SOURCE` records the repository, revision and module digests in the exports.
- **Parity (PAR1–PAR4):** `tests/test_notebook_parity.py` and `tools/validate_release_assets.py` fail when the carried modules, the inline manifest, or the inline pins differ from the repository, or when the notebook is not byte-identical to the generator's output.
- **Model acquisition (MOD1–MOD9, MOD12):** `stage_missing_files(WEIGHTS_DIR, allow_download=True)` fetches only the manifest entries a fresh runtime lacks, at the pinned revision (never `main`); `verify_snapshot` re-hashes every entry and asserts the pinned `model.safetensors` digest and byte count before the model is constructed; `SiglipPipeline.from_pretrained(weights_dir=WEIGHTS_DIR)` loads the verified files (`local_files_only=True`, `trust_remote_code=False`, `use_safetensors=True`) and picks CUDA when it is visible. No cell outside the carried modules calls `huggingface_hub`, `transformers`, `safetensors`, `urllib`, `torch.optim` or the model's towers directly.
- **Data (DAT1–DAT9, ST6):** the default sample is 360 research-grade, CC0-licensed iNaturalist photographs of six bird species (60 per species, one per observer), each pinned in the carried `samples.py` by photo id, byte size and SHA-256 and fetched from `https://inaturalist-open-data.s3.amazonaws.com/photos/<id>/medium.<ext>` (about 39 MB); a cached or fetched file is refused on any mismatch, and every record keeps its observation page and observer login. `build_sample_dataset(seed=SPLIT_SEED)` draws 36 / 8 / 16 per species (216 / 48 / 96) and `check_split_disjoint` asserts no photograph (by decoded-pixel digest) is shared. The template adds a second *External access* bullet naming the bucket, the byte count and the CC0 licence.
- **Stages (§4.1):** `fetch_corpus` + `read_corpus` + `build_sample_dataset` / `load_byod_dataset` + `split_dataset` (sample acquisition) → `validate_dataset` per split + `check_split_disjoint` + `observer_overlap` + refusal probes (validation, with three digests) → `validate_inputs` + `zero_shot_classify` / `retrieve` / `embed_image` with sanity checks + `evaluation_report` on the drawn shapes (inference contract) → `majority_baseline` + `colour_neighbour_baseline` + `pipe.evaluate` on the frozen model with the per-species breakdown and the scientific-name prompt set (baselines) → `pipe.adapt` (bounded fine-tuning) → `pipe.evaluate` on validation and test with the comparison (evaluation) → `zero_shot_classify` + `evaluation_report` on the shapes again (inference) → `pipe.save_artifact` → `SiglipPipeline.from_artifact` with the parity assertion (export and reload).
- **Score semantics (UNC1–UNC4):** sigmoid scores are independent, uncalibrated and prompt-dependent, and the classifier never abstains; accuracy, macro F1 and text-to-image mAP are computed from the model's own `logits_per_image` (own numpy implementations) and none is a human judgement; no acceptance threshold ships. The shapes re-scored after adaptation carry a `sample-sanity` verdict that names the missing dispersion.
- **Baselines and evidence (EVAL6/EVAL10/EVAL11):** the majority floor, the colour nearest neighbour and the frozen model are scored on the same 96 test photographs as the adapted model, on the three metrics and per species; every metric is labelled as one seeded split of one sample with no dispersion estimate, and the notebook says explicitly that the frozen model is already a usable zero-shot classifier, that the measured gain is concentrated on the retrieval view and the worst-separated species, and that a 48-photograph validation split moves accuracy in 2 % steps.
- **Split integrity (SPL1–SPL8):** the split is seeded and image-disjoint; validation (48 photographs) selects the epoch on text-to-image mAP and the test split is used for nothing but the final evaluation; observer overlap between splits is printed as an observation, and the notebook states that images from few photographers or sessions must be split by source.
- **Ceilings (VAL6):** `TEXT_MAX_LENGTH` (64), `DEFAULT_PROMPT_TEMPLATE`, `MAX_IMAGE_SIDE` (4096), the record bounds (8..20,000), the class bounds (2..100), the 64-character label ceiling and the id pattern are stated in the Prerequisites and printed before the model runs; four dataset refusals and one input refusal are demonstrated.
- **BYOD (DAT10–DAT19):** `USE_BYOD` defaults to `False` so the sample path never opens an upload dialog; when enabled, one zip is read member by member (no `extractall`) into the runtime and its `labels.csv` records flow through the same validation, image-disjoint split, baselines, fine-tuning, evaluation, export and reload cells. The expected schema and the privacy guidance are stated in the Prerequisites and in Section 4, and the training split is written to `outputs/siglip_v1_zero_shot_train.csv` in the same shape.
- Licence: the weights are Apache-2.0 and the notebook, README and card say so; the photographs are CC0 1.0 and are not redistributed — the export records the corpus name, release, bucket, byte count and licence under `corpus`.
- `tools/validate_release_assets.py` performs source validation only. It does not satisfy the clean-runtime execution requirement; a release review must confirm that a recorded clean run in `../docs/release-verification.md` matches the notebook revision under review before the status is promoted to `Release-grade`.

## Outputs

The default notebook path writes (under `outputs/`):

- `siglip_v1_zero_shot_train.csv` — the training split's labels table in the BYOD shape
- `siglip_v1_zero_shot_input_manifest.json` — the inference-contract manifest (schema, ceilings, per-image observations, one recorded rejection finding)
- `siglip_v1_zero_shot_evaluation_report.json` — baselines, frozen and adapted metrics on validation and test, the per-species comparison, the adaptation history
- `siglip_v1_zero_shot_shapes.json` — the drawn shapes' rankings before and after adaptation
- `siglip_v1_zero_shot_adapter/` — `adapter.safetensors` + `manifest.json`
- `siglip_v1_zero_shot_result.json` — `NOTEBOOK_SOURCE`, model identity, snapshot, corpus, inference-contract reports, comparison, artifact digest, reload parity, runtime
- `provenance.json`
